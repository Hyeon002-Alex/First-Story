# 공정표 — 3단계: 전투 코어 + 적 AI 구현 순서

- 프로젝트: 라플라스 전기 1부 (Unity / C#)
- 단계: 3단계(구현 절차 세분화 = 공정표)
- 범위: 전투 코어 + 적 AI. **묶음4(거점·성장·장비·보상·저장)는 이 공정표 밖 → 전투 코어 구현 후 별도 진행.**
- 상태: **확정** — 대주제 A~G 순서·경계 고정. 소주제는 구현 중 가감 가능(개수 가변 방침).
- 선행 문서(설계도 = 2단계): `유닛·스킬데이터`, `묶음1`, `묶음2`, `묶음3`, `적AI 결정로직` 인계문서.
- 기준 문서: `GDD v0.4.1`, `v0.1.0 공개범위 결정문서`.
- 성격 구분: **2단계 = 설계도(무엇을 어떤 구조로), 3단계 = 공정표(어떤 순서로).** 여긴 순서만. 구조는 선행 인계문서가 진실원.

---

## 0. 이 공정표의 원칙

- **대주제(A~G) = 독립 검증 가능한 완결 블록.** 그것만으로 로그 기반 "의도대로 도는지" 단독 확인 가능. 대주제 경계 = 검증 트리거 = 인계문서 트리거 = 채팅 전환 지점.
- **소주제(A-1…) = 구현·커밋 최소 단위.** 한 번에 집중해 짤 응집된 덩어리(보통 클래스 1~2개). 단독 미완결. 완료 시 GitHub 커밋.
- **의존 순서 고정.** 위 대주제가 아래의 전제. B의 더미 intent 트릭으로 적 AI(G)를 맨 뒤로 미뤄도 C~F 검증 가능(§9 참조).
- **구현 원칙(GDD 9.1)**: 밸런스 값 데이터 분리 / 정적·런타임 분리 / 로그 프로토타입 먼저, UI는 나중 / 사용자 주도·AI 리뷰.

## 1. 대주제 의존 그래프

```
A 데이터·유닛 뼈대  (의존: 없음)
  │
B AP + 턴 골격      (의존: A)   ← 3단계에 더미 intent 심음
  │
C 한 방 실행 파이프  (의존: B)
  ├──────────────┬─────────────┐
D 대응·방어·특수   E 상태이상·턴종료  G 적 AI 결정
  (의존: C)        (의존: C, D와 병렬)  (의존: C, D / B 더미 교체)
  └──────┬───────┘
F 웨이브·전투불능·승패 (의존: D, E)
```

- E는 C 이후 D와 **병렬 가능**(서로 독립). 세션 사정 따라 D→E 또는 E→D.
- G는 C·D 이후 아무 때나. **B의 더미 intent를 진짜로 교체**하는 게 G의 실체.
- F는 D·E 둘 다 있어야(전투불능 전이 = D 사망판정 + E 틱, 상태소거 = E).

## 2. A. 데이터·유닛 뼈대  *(의존: 없음)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| A-1 | 정적 데이터 클래스: UnitStats · SkillData · AllyUnitData · EnemyUnitData (읽기전용, 삭제 필드 제외) | 유닛·스킬 §4.3, GDD 9.3 |
| A-2 | 런타임 유닛: BattleUnit / AllyUnit / EnemyUnit + RuntimeStats(컴포지션) | 유닛·스킬 §2 |
| A-3 | 유효스탯 단일 접근자(기본+보정) + 저수준 쓰기 통로(ModifyHp·SetXxx) + IsIncapacitated 자리 | 유닛·스킬 §3(3층) |

- **검증**: 유닛 생성 → HP·유효스탯(공격·방어·속도) 읽기, SkillData 참조 로그. 값이 정적+런타임 2층으로 나오나.
- **주의**: 유닛은 얇게 — 계산·판단 로직 넣지 말 것. 통로·불변식만.

## 3. B. AP + 턴 골격  *(의존: A)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| B-1 | APSystem(stateless): RecoverAll `min(+2,6)` · CanAfford · Consume | 묶음1 3-A |
| B-2 | ActionCommand(단일 클래스 + 팩토리, 실행 로직 없음) | 묶음1 3-C |
| B-3 | BattleFlowSystem 9단계 골격 + 7단계 실행 골조(정렬 1회·유효성 재검사). **구멍 스텁, 3단계는 더미 intent** | 묶음1 3-D |

- **검증**: 빈 턴 루프가 9단계 순서대로 돌고, AP `min(+2,6)` 절삭(첫 턴 특례 없음) 로그.
- **더미 intent(§9)**: 3단계에서 각 적에게 "첫 skillId·첫 생존 아군" 임시 intent 부여. G에서 교체될 자리.
- **함정**: 첫 턴 AP 분기 만들지 말 것(절삭이 통일). 7단계 정렬은 1회만(둔화는 다음 턴).

## 4. C. 한 방 실행 파이프  *(의존: B)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| C-1 | CombatCalculator(순수): CalcDamage·CalcHealing·CalcShield. **예상=실제의 열쇠** | 묶음2 3-B |
| C-2 | DamageSystem / HealingSystem(계산 결과 유닛 통로로 적용, 보호막 흡수) | 묶음2 3-B |
| C-3 | DirectionSystem(공격방향 vs 방어자자세 → 배율, 대칭·데이터화) | 묶음2 3-C |
| C-4 | TargetingSystem 기본(targetRule + intent 대상, 보호는 D에서) | 묶음2 3-E |
| C-5 | ActionResolver 12스텝 뼈대(회피·붕괴·상태이상 스텝은 스텁) | 묶음2 2-A |

- **검증**: 공격 명령서 → 방어·방향 배율 반영 최종 피해, **예상==실제** 로그(같은 Calculator 호출).
- **주의**: 배율은 밖에서 판정해 숫자 주입. 계산 함수는 곱하기만(방어보정 `100/(100+방어)`만 안).

## 5. D. 대응·방어·특수 판정  *(의존: C)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| D-1 | ProtectionSystem(보호=전원 고정행동, 관계형) → TargetingSystem 대상 갈아끼움 | 묶음2 3-E |
| D-2 | EvasionSystem(횟수형·최대3·즉시소모) → 파이프 5스텝 | 묶음2 3-F |
| D-3 | Break/CrackSystem(게이지 누적·발생·받는피해증가 조회) + 붕괴 행동취소(actedThisTurn·intent 무효) | 묶음2 3-D |
| D-4 | 방향방어·자세 배선(RuntimeStats 방어방향·약점방향, 대응단계 5·6 조율) | 묶음2 3-C·3-E |

- **검증**: 보호로 대상 갈림 / 회피 1회로 스킬 통째 무효 / 붕괴로 미행동 적 행동취소 / 방향 일치·불일치·약점 배율 로그.
- **주의**: 파이프 순서 8~11(피해→사망→붕괴누적→발생)이 붕괴 소급·사망동시 함정을 자동 해결(별도 처리 금지).

## 6. E. 상태이상 + 턴종료  *(의존: C, D와 병렬 가능)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| E-1 | StatusEffectSystem: 조각 리스트(안3) · effectKind 6종 · 면역 · 정화 · 중첩(max) · 지속피해 스냅샷 | 묶음3 3-A~3-E |
| E-2 | 8단계 순서: TickAll → 사망/전투불능 전이 → DecrementAndExpire → 전투상태 만료 | 묶음3 §4 |
| E-3 | 유효스탯에 상태 파생 반영(GetActiveComponents 소비) + 지연틱(적용턴 int) | 묶음3 3-E |

- **검증**: 화상 지연틱(적용턴 스킵) / 중첩 강한것·긴지속 / 화상+중독 독립 / 둔화 다음턴 / 만료 제거 로그.
- **주의**: 지연틱은 `현재턴 > 적용턴` 절대값 판정(bool 발동대기 금지). 8단계 순서에서 마지막 틱 보존.

## 7. F. 웨이브·전투불능·승패  *(의존: D, E)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| F-1 | 전투불능 전이(IsIncapacitated 단일 플래그, HP0 핸들러 수렴) | 묶음3 3-F |
| F-2 | WaveSystem: 전환 시퀀스 · 아군 HP1 복귀 · 상태 소거 이원화(ClearAll/ClearNormal) | 묶음3 3-F |
| F-3 | 9단계 판정: 전멸(먼저) · 승리 · 웨이브 전환 · 페이즈 전환(별 경로) | 묶음3 3-F |

- **검증**: 전투불능→다음 웨이브 HP1 복귀(AP 유지) / 웨이브 유지·제거 목록 / 동시 HP0 패배 / 페이즈 전환 게이지·자세 리셋 로그.
- **주의**: 생존 유닛 일반상태 유지 vs 복귀 유닛 제거(ClearNormal 비대칭). 전멸 판정 < 승리 판정 순서.

## 8. G. 적 AI 결정  *(의존: C, D — B 더미 intent 교체)*

| 소주제 | 내용 | 근거 문서 |
|---|---|---|
| G-1 | BehaviorCondition(안i struct + 팩토리 + Evaluate 순수) + BehaviorPatternData(우선순위 규칙) | 적AI 3-B |
| G-2 | DataDrivenBehavior(첫매치 · 대상정책 · tie-break 슬롯인덱스 고정 · stateless) | 적AI 3-B·3-C |
| G-3 | EnemyBehaviorSystem(팩토리 바인딩 · 3단계 배선 · SetIntent) — **B 더미 intent 교체** | 적AI 3-A |
| G-4 | 보스 계약 자리(IEnemyBehavior 구현부 스텁, 안P 상태 원칙만) | 적AI 3-D |

- **검증**: 조건별 스킬 선택(HP임계·턴수) / 대상정책 우선순위 / **동점 tie-break 결정론**(같은 상태 반복 → 같은 결정) 로그.
- **주의**: 무작위 금지(0.5 절대선). 조건·정책 실제 값은 GPT 잡몹 스펙 gated — 구조만 구현, 값은 데이터 자리.

## 9. B의 더미 intent 트릭 (공정표 핵심)

- **문제**: 턴 루프에 적이 있으려면 3단계 intent가 필요. 근데 적 AI(G)를 먼저 짜면 C~F 없이 AI를 테스트 못 함(순서 역전).
- **해법**: B-3에서 3단계에 **더미 intent 주입** — 각 적에게 "첫 skillId + 첫 생존 아군" 고정 부여. C~F는 이 더미로 실행 파이프·상태·웨이브를 전부 검증.
- **G에서 교체**: G-3의 EnemyBehaviorSystem이 더미를 진짜 Decide 결과로 갈아끼움. 파이프·IntentSystem은 불변(intent 모양 동일).
- **효과**: 적 AI를 맨 뒤에 둬도 전체 코어 검증 가능. AI 결정 로직과 전투 실행이 깨끗이 분리됨.

## 10. 세션·검증·문서 규칙 (방침 재확인)

- **채팅 분리**: A~G를 한 채팅에 다 못 넣음. 대주제 1~2개씩 세션 분리. 세션 시작 시 선행 인계문서 Knowledge 확인, 없으면 요청.
- **커밋**: 소주제 완료 = GitHub 커밋(최소 단위).
- **대주제 완료 3종 트리거 일치**: 대주제 동작 검증(로그) + 인계문서 생성 + 채팅 전환. 검증 통과 못 하면 다음 대주제 진입 금지.
- **역할**: 구현 = 영현 주도, Claude = 리뷰·힌트·대안. (입문자라 A 대주제는 스캐폴딩 보강 가능.)
- **임시 스냅샷**: 채팅 과다 시 소주제 도중이라도 `진행중` 인계문서 스냅샷 후 새 채팅.

## 11. 다음 착수 지점

- **A 대주제(데이터·유닛 뼈대)부터 구현 = 4단계.** 새 채팅에서 진행.
- 착수 조건: 2단계 인계문서 5종 + 본 공정표가 Knowledge에 있어야 맥락 연결.
- **묶음4는 G(전투 코어 완료) 이후 별도 진행.** 저장(save/load) 설계 시 적AI 인계문서 부채(보스 내부 상태 직렬화) 회수 필수.
- 5단계(통합 검증)는 A~G 전부 구현 후.
