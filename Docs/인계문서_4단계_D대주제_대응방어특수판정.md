# 인계문서 — 4단계 D대주제: 대응·방어·특수 판정

**상태: 완료** (대주제 통합 검증 통과)

D-1 보호 · D-2 회피 · D-3 붕괴/균열 · D-4 방향방어·자세. C가 남긴 seam 4곳을 소유 시스템으로 채우고, 파이프 실행 스텝(5·6·10·11)과 턴루프 배선(Step1·7·8, IsStillValid)을 완성함.

---

## 1. 이번 대주제 산출물

### 신규 클래스 (3)
| 클래스 | 책임 |
|---|---|
| `ProtectionSystem` | 보호 관계(피보호자→보호자) 보관·조회·소거. 상태 있는 인스턴스 |
| `EvasionSystem` | 회피 보유 조회 / 부여(상한3) / 소모(즉시). static, 상태 없음 |
| `BreakCrackSystem` | 게이지 누적·발생·받는피해증가 조회·만료. static, 상태 없음 |

### 수정 클래스 (9)
| 클래스 | 변경 |
|---|---|
| `TargetingSystem` | `Resolve` 4인자(+protection). 보호 리다이렉트 3스텝 구현 |
| `ActionResolver` | 4인자(+intent). `Execute(cmd,turn)`. 회피 5·붕괴 10·11 · 방향/붕괴 배율 조회 |
| `BattleFlowSystem` | Step1 acted 리셋 · Step7 acted 세팅+turn 전달 · Step8 만료(보호·붕괴·자세) · IsStillValid 붕괴취소 |
| `IntentSystem` | intent 무효표시(`Cancel`/`IsCancelled`). ClearAll에 포함 |
| `IActionExecutor` | `Execute(command, currentTurn)` |
| `RuntimeStats` | 받는피해증가 배율+만료턴 · 방어방향+약점방향 저장·통로 |
| `BattleUnit` | `actedThisTurn` · 받는피해증가/자세 접근자 · `GetDefenseStance()` 조립 |
| `AllyUnit` | `StanceIsActive => true` (능동) |
| `EnemyUnit` | 게이지 max 접근자 · `StanceIsActive => false` (패시브) |

## 2. 핵심 구조 (파이프·턴루프에서 D가 채운 지점)

```
[한 행동 실행 파이프 — ActionResolver]
  1~4 대상 결정 ── TargetingSystem
        └ 3 보호 리다이렉트 ····· ProtectionSystem.GetProtector (D-1)
  5 회피 판정 ················· EvasionSystem.HasEvasion/Consume (D-2)  → 걸리면 통째 무효
  6 방향 배율 ················· DirectionSystem.GetMod(공격방향, target.GetDefenseStance()) (D-4)
  7 계산 ····················· CombatCalculator (dir × break 곱)
  8 적용 → 9 사망판정
  10~11 붕괴/균열 ············· BreakCrackSystem.Accumulate/CheckAndTrigger (D-3)  ※생존·적만
  12 상태이상 ················· 미구현 (E)

[글로벌 턴 루프 — BattleFlowSystem]
  Step1 ── 전원 actedThisTurn 리셋 (D-3)
  Step7 ── Execute(cmd, turnNum) 후 actor.SetActed(true) (D-3)
  Step8 ── protection.ClearAll(D-1) + 붕괴 만료(D-3) + 아군 자세 clear(D-4)
  IsStillValid ── IntentSystem.IsCancelled → 붕괴 행동취소 스킵 (D-3)
```

**배율 합성**: 방향 배율 × 붕괴 배율이 `CombatCalculator` 안에서 곱해짐 (예: 약점 1.25 × 붕괴 1.50 = 1.875, floor 적용).

## 3. 공개 인터페이스 (E·후속이 호출·의존)

```
ProtectionSystem
  void SetProtect(protector, protectee)   // 6단계
  BattleUnit GetProtector(protectee)      // 대상 파이프 3
  void ClearAll()                         // 8단계

EvasionSystem (static)
  bool HasEvasion(unit)
  void Grant(unit, count)                 // 상한3 clamp
  void Consume(unit)                      // 즉시 1

BreakCrackSystem (static)
  float GetDamageMod(target)              // 받는피해증가 배율 조회(순수)
  void  Accumulate(enemy, breakAmount)    // 상태 중 스킵
  bool  CheckAndTrigger(enemy, currentTurn, intentSystem)
  void  ExpireDamageMod(unit, currentTurn) // 8단계 만료

BattleUnit
  bool ActedThisTurn / void SetActed(bool)
  float DamageTakenMod / int DamageTakenModExpireTurn / void SetDamageTakenMod(mod, expireTurn)
  AttackDirection DefenseDirection / WeaknessDirection
  DefenseStance GetDefenseStance()        // 방향값+IsActive 조립
  void SetStance(defenseDir, weaknessDir) / void ClearStance()

IntentSystem
  void Cancel(enemy) / bool IsCancelled(enemy)

IActionExecutor
  void Execute(command, currentTurn)      // ★시그니처 변경
```

## 4. 확정 설계 결정

**D-1 보호**
- `ProtectionSystem` 인스턴스는 BattleFlowSystem 소유 + ActionResolver 주입 (IntentSystem 선례). 6·8단계와 대상 파이프가 같은 인스턴스 공유.
- 저장 방향 피보호자→보호자 (조회 O(1), 순회 미노출 → Dictionary 순서 부채 회피).
- 리다이렉트는 `Single`만(FixedTarget·Area 제외), **살아있는 보호자로만** 교체.
- 순서: 리다이렉트(3) → 최종 생존확인(4) (GDD 5.9).
- 소거 = Step8 (보호 한 턴 한정).

**D-2 회피**
- `EvasionSystem` static. 카운트는 RuntimeStats.
- **상한3 = 시스템 소유** (밸런스 규칙). 통로는 음수만 방지. → 묶음2의 "유닛 통로 최소 불변식" 서술을 코드에 맞춰 폐기(레포 SSOT 우선).
- **HasDamage 게이트**: 회피 판정은 공격 계열만. 회복·보호막은 회피 무관(파이프 5스텝이 계산 앞이라 게이트 없으면 우호 스킬 씹힘).
- 즉시 소모(안1).

**D-3 붕괴/균열**
- `Execute`에 `currentTurn` 인자 추가(인터페이스 변경). 순환참조·공유객체 회피, E 지연틱 재사용.
- `ActionResolver` 4인자(+intent). Cancel이 파이프 소유(인과).
- 게이지 단일 + `isBoss ? MaxCrackGauge : MaxBreakGauge` 임계. 일반=붕괴, 보스=균열.
- 받는피해증가 1.50 공통. **행동취소는 붕괴만**(균열 X), `!IsBoss && !ActedThisTurn`.
- 발생 시 게이지 0(초과분 삭제), **상태 중 재누적 불가**(IsBroken 가드). 소급 없음·사망동시 발생X는 파이프 순서로 강제.
- `actedThisTurn` = BattleUnit 플래그. 만료 = Step8.

**D-4 방향방어·자세**
- 방어방향·약점방향 = RuntimeStats **동적** 저장 (적 자세도 스킬 부여, GDD 5.7).
- `IsActive` = 유닛 타입 결정(abstract). 아군 능동(불일치 0.75) / 적 패시브(불일치 1.00). DirectionSystem은 타입 분기 없이 배율만 읽음.
- 약점 우선은 `DirectionSystem.GetMod` 기존 로직이 처리(D-4 추가코드 없음).
- 만료 = **아군 자세만** Step8 clear(한 턴). 적 패시브 자세는 스킬 지속이라 대상 아님.

## 6. 기술 부채 (카테고리별)

### [E 착수 전 결정 필요 — 중요]
- **부채-1 · DamageTakenMod 단일 채널 충돌**: 붕괴가 쓰는 받는피해증가 필드를 E의 받는피해 증감 상태이상도 써야 함. 현재 통로는 단일 값 덮어쓰기라 동시 활성 시 하나가 사라짐. 또 `IsBroken`이 `> 1.00f`로 붕괴를 판정하므로, 상태이상이 **받는피해 감소**(<1.00)를 이 필드에 쓰면 붕괴 상태 인식이 깨짐. → **붕괴 채널과 상태이상 채널 분리(권장)** vs 단일 채널 합성규칙(곱/최대/합)을 E 착수 시 결정.
- **부채-2 · Step8 받는피해증가 만료가 적만 순회**: 현재 `foreach EnemyUnit`. 붕괴는 적만이라 정확하나, E가 아군에 받는피해 증감을 부여하면 아군 만료가 영구 누락. → E에서 아군 받는피해증가가 생기면 `Step8`을 `AllUnits()` 순회로 확장.

### [불변식 — 호출측 책임에 의존]
- **다중 피보호자 미강제**: `ProtectionSystem`은 1피보호자=1보호자는 보장하나, 한 보호자가 여러 피보호자를 등록하는 것은 구조상 허용. GDD의 "보호=행동 1회 소모(1명)"는 6단계 호출측 제약에만 의존. v0.1.0 무해(호출측 1회).

### [범위 확인 필요]
- **다단 공격(GDD 5.13)**: 묶음2가 "다단 회피·붕괴 1회 제한은 Resolver 층" 예고. 현재 1스킬=1히트라 분할 없음. v0.1.0 스킬에 실제 다단 유무 확인 → 있으면 E 이후 별도 작업.

### [기존 부채 — 유지]
- UnityEngine 의존(`Debug.Log`) — 헤드리스 전환 시 로거 추상화.
- Dictionary 반복 순서 비결정성(`IntentSystem.AllIntents`) — 순서 의존 결정 금지(고우선).
- balance 상수 데이터 미이관 — 방향 배율(0.30/0.75/1.25), 붕괴 1.50, 회피 상한3이 코드 상수. BattleConfig/데이터 에셋 마이그레이션 대상.
