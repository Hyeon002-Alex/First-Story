## 1. 폴더 구조 (확정)

**원칙: 코드(.cs)와 에셋 인스턴스(.asset)는 다른 물건 → 다른 트리.**
`SkillData.cs`(틀) = `Scripts/`, `Skill_Fireball.asset`(찍어낸 데이터) = `GameData/`.

```
Assets/
├── Scripts/                      ← .cs만. asmdef로 3층 강제.
│   ├── Data/                     ← [Laplace.Data] 정적 데이터 "정의". 의존 없음.
│   │   ├── Enums/                ← AttackDirection.cs, TargetRule.cs (하위폴더도 같은 asmdef)
│   │   ├── UnitStats.cs
│   │   ├── SkillData.cs
│   │   ├── AllyUnitData.cs
│   │   ├── EnemyUnitData.cs
│   │   └── Laplace.Data.asmdef
│   ├── Core/                     ← [Laplace.Core] 런타임 유닛·상태 그릇. Data 의존.
│   │   ├── RuntimeStats.cs
│   │   ├── BattleUnit.cs
│   │   ├── AllyUnit.cs
│   │   ├── EnemyUnit.cs
│   │   └── Laplace.Core.asmdef
│   ├── Systems/                  ← [Laplace.Systems] 규칙·판정. Core·Data 의존. (B~F 여기)
│   │   ├── AI/                   ← (G) IEnemyBehavior + 보스 전용 스크립트. 예약.
│   │   └── Laplace.Systems.asmdef
│   └── UI/                       ← [Laplace.UI] 표시 계층. 나중. Core 읽기만.
│
├── GameData/                     ← SO "인스턴스"(.asset). 코드 아님.
│   ├── Skills/                   ← Skill_*.asset
│   └── Units/{Allies, Enemies}/  ← Ally_*.asset / Enemy_*.asset
│
├── _Scratch/                     ← 임시·검증(BattleUnitProbe 등). 커밋 제외. asmdef 안 둠.
├── Scenes/
├── Prefabs/                      ← 나중
└── Art/                          ← 나중
```

- `GameData/`를 `Scripts/Data`와 이름 분리 — 코드/에셋 물리 격리(커밋·grep 뒤엉킴 방지).
- `Enums/` 하위폴더: 곧 늘어남(effectKind 6종·category 등 묶음3). 폴더 루트 asmdef 하나면 하위 전부 커버 → 별도 asmdef 불필요.
- `_Scratch/`엔 asmdef 안 둠 → 기본 어셈블리(Assembly-CSharp)에 남아 `autoReferenced` asmdef들을 자동 참조 → 프로브 수정 0으로 돎.
- **안 만듦**: `Resources/`(항상 빌드 포함+언로드 제어 불가 → 필요 시 Addressables), `Editor/`(커스텀 인스펙터·검증툴 생길 때).
- **이동 규칙**: 폴더·파일 이동은 **반드시 Unity 프로젝트 창 안 드래그**. OS 탐색기 이동 금지(.meta GUID 끊겨 에셋 참조 Missing).

## 2. asmdef 3층 (레이어 컴파일 강제)

의존 방향 = `Systems → Core → Data`. Data가 Core/Systems 타입 참조하면 **컴파일 에러**로 막힘(관례 → 강제 승격).

| 어셈블리 | 위치 | references |
|---|---|---|
| Laplace.Data | Scripts/Data | (없음) |
| Laplace.Core | Scripts/Core | Laplace.Data |
| Laplace.Systems | Scripts/Systems | Laplace.Core, Laplace.Data |

- 전부 `autoReferenced: true` → Assembly-CSharp(프로브 등)가 자동으로 봄.
- **namespace 없음**(유보): 이름 충돌 임박 아니고 10파일 재들여쓰기 비용 회피. 필요 시 file-scoped(`namespace X;` 1줄)로 값싸게 추가.

## 3. 산출물 (클래스·기능 목록)

**A-1 정적 데이터** — `Scripts/Data/`
- `AttackDirection` (enum): `None / High / Mid / Low` — 회복·정화·보호·정보·도발은 None.
- `TargetRule` (enum): `Single / Area / FixedTarget / Self` — 비파괴적 추가 가능.
- `UnitStats` (**`[Serializable] struct`**): 기본 스탯 4종(maxHp/attack/defense/speed). null 불가, 값 복사. 유닛데이터에 인라인.
- `SkillData` (SO): 고유행동·스킬·아이템 통합 정의(구조1). 유닛은 `skillId` 문자열로 참조.
- `AllyUnitData` (SO): 아군 정적 정의. `List<string>` 필드 초기화됨.
- `EnemyUnitData` (SO): 적 정적 정의. `List<string>` 필드 초기화됨.

**A-2/A-3 런타임 유닛** — `Scripts/Core/`
- `RuntimeStats` (POCO): 런타임 변동 상태(현재HP·보호막·회피) + HP/shield/evasion 쓰기 통로.
- `BattleUnit` (abstract): 공통 부모. 유효스탯 접근자·쓰기 통로 위임·`IsIncapacitated`.
- `AllyUnit` : `BattleUnit` — AP 보유.
- `EnemyUnit` : `BattleUnit` — 단일 붕괴/균열 게이지.

## 4. 핵심 구조 (관계 + 책임 1줄)

```
[정적층 — SO 에셋 / 편집 대상]              [런타임층 — 코드 new / 전투 중 변동]

SkillData ──(skillId 참조)                 BattleUnit (abstract)
AllyUnitData  ─ baseStats ─┐                ├─ _baseStats : UnitStats(struct, 값 복사)
EnemyUnitData ─ baseStats ─┤                ├─ _runtime   : RuntimeStats(컴포지션)
                           │                ├─ _isIncapacitated : bool
UnitStats(struct) ◀────────┘                ├─ AllyUnit  : + _currentAp,  _data:AllyUnitData
  (maxHp/atk/def/spd)                       └─ EnemyUnit : + _gauge(단일), _data:EnemyUnitData

RuntimeStats : _maxHp / _currentHp / _shield / _evasionCount (+ 쓰기 통로)
```

- **UnitStats**: 정적 기본 스탯. struct라 `BaseStats` 접근 시 복사본 반환(원본 SO 불변).
- **SkillData**: 행동 하나 정의. 순수 데이터, 실행 로직 없음.
- **AllyUnitData/EnemyUnitData**: 유닛 종류 정적 원본. 읽기 전용.
- **RuntimeStats**: 전투 중 변하는 값 소유. 재시작 시 이것만 새로 생성.
- **BattleUnit**: 공통 런타임 골격. 유효스탯 단일 경로·저수준 통로 소유. 규칙은 미소유(시스템 몫).
- **AllyUnit/EnemyUnit**: 진영별 고유 상태 + 자기 데이터 참조.

원칙 준수: 3레이어(System→Unit→Data, 이제 asmdef 강제) · thin unit + system owns logic · 데이터-행동 분리 · 절대적 결정론(무작위 0).

## 5. 공개 인터페이스 (B/C 이하가 호출·의존)

### BattleUnit (abstract)
```
// 읽기 — 상태
int  MaxHp / CurrentHp / Shield / EvasionCount
bool IsIncapacitated
// 읽기 — 유효 스탯 (단일 경로: 기본 + 보정, 보정 현재 0 seam, 하한 0 클램프)
int  EffectiveAttack / EffectiveDefense / EffectiveSpeed
// 쓰기 통로 (최소 불변식만. delta·값은 시스템이 계산해 밀어넣음)
void ModifyHp(int delta)        // [0, maxHp] 클램프
void SetShield(int value)       // >=0
void SetEvasion(int value)      // >=0 (상한 3은 EvasionSystem 몫)
void SetIncapacitated(bool value) // 전이 판단은 F-1, 여기선 세팅만
```

### RuntimeStats
```
RuntimeStats(int maxHp)         // currentHp=maxHp, shield=0, evasion=0
int  CurrentHp / Shield / EvasionCount
void ModifyHp(int delta) / SetShield(int) / SetEvasion(int)
```

### AllyUnit : BattleUnit
```
AllyUnit(AllyUnitData data)
int  CurrentAp                  // 시작 0
string UnitId
IReadOnlyList<string> EquippedSkillIds
void SetAp(int value)           // >=0 (회복 min(+2,6)·소모는 APSystem 몫)
```

### EnemyUnit : BattleUnit
```
EnemyUnit(EnemyUnitData data)
int  CurrentBreakOrCrackGauge   // 시작 0. 단일 필드, isBoss로 붕괴/균열 구분
bool IsBoss
string EnemyId
IReadOnlyList<string> SkillIds
string BehaviorPatternId
void SetGauge(int value)        // >=0 (누적·발생·초기화는 Break/CrackSystem 몫)
```

### SkillData (읽기 전용 프로퍼티)
```
string SkillId | int ApCost
float DamageCoefficient  | int FixedDamage
float HealingCoefficient | int FixedHealing
float ShieldCoefficient  | int FixedShield
int BreakAmount | AttackDirection Direction | TargetRule TargetRule
IReadOnlyList<string> EffectIds     // 부여 상태이상 ID
bool CleansesNormalStatus           // 일반 상태 정화(부여의 반대)
bool IsUnavoidable                  // 회피불가(GDD 5.11)
```

### AllyUnitData / EnemyUnitData / UnitStats (읽기 전용)
```
AllyUnitData : UnitId, UniqueActionId, AvailableSkillIds, EquippedSkillIds, BaseStats
EnemyUnitData: EnemyId, IsBoss, BreakGaugeMax, CrackGaugeMax, SkillIds, StatusImmunityIds, BehaviorPatternId, BaseStats
UnitStats    : MaxHp, Attack, Defense, Speed   (struct — 접근 시 값 복사)
```

## 7. 검증 결과 — **통과**

임시 프로브(`BattleUnitProbe`, `_Scratch/`, 커밋 제외)로 확인:
1. 생성 직후 HP·유효 공/방/속·AP·게이지 정상.
2. **HP 2층**: `ModifyHp`로 런타임층만 변동, 정적층 고정. 과다 피해→0, 과다 회복→maxHp 클램프.
3. 통로 동작(Shield/Evasion/Ap/Gauge) 반영·음수 방지.
4. `IsIncapacitated` 토글 반영. `IsBoss` 진영 구분. SkillData 필드 참조 로그.
- 공정표 A 검증 기준 충족. asmdef 3층 재컴파일 에러 0, SO 에셋 Missing 0.

## 8. 구현 중 확정된 설계 결정

- **정적 데이터 = ScriptableObject** (UnitStats만 `[Serializable] struct` 내장).
- **런타임 유닛 = POCO** (SO/MonoBehaviour 아님). 데이터-런타임 분리.
- **BattleUnit = abstract**.
- **UnitStats = struct**(리뷰 #5): null 불가로 NRE 벡터 제거, 값 복사로 공유 mutation 차단. `readonly struct` 아님(Unity 직렬화가 readonly 필드에 못 씀); 외부 불변성은 get-only 프로퍼티로 확보.
- **List 필드 초기화**(리뷰 #4): 모든 `List<string>`에 `= new List<string>()`. `new()` 축약 안 씀(구버전 Unity 대비).
- **asmdef 3층 + namespace 유보**(리뷰 #6).
- **정화 = `bool CleansesNormalStatus`**(범주형 전체, GDD 5.12). 선택 정화 미지원(빚).
- **유효스탯 = 단일 경로** `기본 + 보정`. 보정원 미도착 → modifier getter 0(seam). 소비처는 `Effective*`만 읽음. 하한 0 클램프.
- **통로 불변식 원칙**(전 시스템 적용): 통로는 도메인 이탈만 막음. HP만 `[0,maxHp]`, 나머지 스칼라는 음수만 방지. 상한·발생·회복 등 규칙은 시스템 소유. 통로에 밸런스 값 안 박음.
- **게이지 = EnemyUnit 단일 필드**, `isBoss` 구분.
- **`IsIncapacitated` = 플래그 자리 + set 통로만**. 전이 판단 F-1, 복귀 F-2.
