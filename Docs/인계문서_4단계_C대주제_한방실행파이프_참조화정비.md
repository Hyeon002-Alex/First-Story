# 인계문서 — 4단계 C대주제: 한 방 실행 파이프 + 참조화·displayName 정비

- **상태**: `완료`
- **단계**: 4단계(구현)
- **대주제**: C — 한 방 실행 파이프(ActionResolver 12스텝)
- **포함 범위**: C-1 ~ C-5 전체 + C 완료 후 진행한 **참조화·displayName 독립 정비 커밋**
- **의존**: A(데이터·유닛 뼈대), B(AP·명령서·intent·턴루프 골격)
- **다음 착수**: D대주제(D-1 보호 → D-2 회피 → D-3 붕괴 → D-4 방향방어·자세)

---

## 0. 한눈 요약

C대주제 = B가 남긴 `IActionExecutor.Execute` 구멍을 **ActionResolver(12스텝 파이프)**로 채움. 계산·판정·적용을 전부 하위 시스템에 위임하는 오케스트레이터. C에서 파이프 뼈대 + 대상/방향/계산/적용을 구현하고, 보호(D-1)·회피(D-2)·붕괴(D-3)·상태이상(E) 스텝은 seam 스텁으로 남김.

C 완료 후, 문자열 ID 참조를 인스펙터 직접 참조로 전환(기존 부채 #3 해소)하고 `DisplayName` 필드를 추가하는 **정비 커밋**을 별도로 진행함. 이 정비는 A 데이터 타입·런타임 유닛·B 리졸버만 건드리며 C~G 파이프 코드에는 무영향.

## 2. 핵심 구조

### 레이어 (asmdef 컴파일 강제)

```
Systems  →  Core  →  Data
(규칙·판단)  (통로·불변식)  (저장값)
```

- **DefenseStance만 Data층**(자세는 저장값 성격, AttackDirection에만 의존). 나머지 C 산출물은 전부 Systems층.
- Systems는 Core·Data를, Core는 Data를 참조. 역방향 금지(컴파일 차단).

### 한 방 실행 파이프 12스텝 (ActionResolver가 소유)

```
ActionResolver.Execute(command)          ← BattleFlowSystem 7단계가 각 행위자마다 호출
│
├ command.Skill == null → no-op 로그 (EndTurn / 대응행동은 파이프 밖)
│
├ [1~4] TargetingSystem.Resolve(command, allies, enemies) → TargetingResult
│   1. 후보 = targetRule + command.Target(예정대상)
│   2. 고정대상 확인(FixedTarget이면 3 건너뜀)
│   3. 보호 리다이렉트          … ★D-1 스텁(TargetingSystem 내부)
│   4. 생존 확인 → 죽었으면 TargetLost=true → 행동 취소
│
└ 대상별 루프 (범위면 각 대상마다 5~12) : ResolvePerTarget()
    5. 회피 판정               … ★D-2 스텁(항상 진행)
    6. 방향 배율 = DirectionSystem.GetMod(skill.Direction, 자세)
                               … C에선 자세=DefenseStance.None → 항상 1.00 (★D-4가 실제 자세 배선)
    7. 계산 = CombatCalculator (배율 주입, 순수)   [피해/회복/보호막 독립 분기]
    8. 적용 = DamageSystem.Apply / HealingSystem.Apply / ShieldSystem.Grant
    9. 사망 판정 = HP 0 감지 로그만 (★전투불능 전이는 F)
    10~11. 붕괴/균열 누적·발생   … ★D-3 스텁
    12. 동반 상태이상 적용       … ★E 스텁
```

### 각 시스템 책임 1줄

- `CombatCalculator` — 스탯·계수·주입배율 → 숫자. 상태 없음, UnityEngine 미의존. 계산만.
- `DamageSystem`/`HealingSystem`/`ShieldSystem` — 숫자를 유닛 통로로 적용. 계산 안 함.
- `DirectionSystem` — 방향 대칭 판정. 진영(아군/적) 모름. 배율값 단일 소유.
- `TargetingSystem` — 대상 조회. 상태 안 바꿈.
- `ActionResolver` — 위를 순서대로 호출. 파이프 순서만 소유, 규칙은 각 시스템에 귀속.

## 3. 공개 인터페이스 (D가 호출·의존할 멤버)

```csharp
// === C-1 ===
readonly struct DamageResult { int FinalDamage; float DirectionMod; float BreakMod; }

static class CombatCalculator
{
    DamageResult CalcDamage(int attack, float damageCoefficient, int fixedDamage,
                            int defense, float directionMod, float breakMod);   // 버림1회→최소1
    int CalcHealing(int attack, float healingCoefficient, int fixedHealing, float receivedHealingMod);
    int CalcShield(int attack, float shieldCoefficient, int fixedShield);
}

// === C-2 ===
readonly struct DamageApplication { int ShieldAbsorbed; int HpLost; }

static class DamageSystem  { DamageApplication Apply(BattleUnit target, int finalDamage); }
static class HealingSystem { void Apply(BattleUnit target, int amount); }
static class ShieldSystem  { void Grant(BattleUnit target, int amount); }   // Shield += amount 가산

// === C-3 ===
readonly struct DefenseStance
{
    AttackDirection Defense;   // None=방어자세 없음
    AttackDirection Weakness;  // None=약점 없음(아군 항상 None)
    bool IsActive;             // 능동(아군 방향방어)=true / 패시브(적 자세)=false
    static DefenseStance None; // (None, None, false)
}

static class DirectionSystem
{
    // 배율 단일 소유(BattleConfig SO 미생성, static readonly)
    float NoneMod=1.00; float MatchMod=0.30; float WeaknessMod=1.25;
    float AllyMismatchMod=0.75; float EnemyMismatchMod=1.00;
    float GetMod(AttackDirection attackDir, DefenseStance stance);
    // 우선순위: 방향없음 → 약점 → 일치 → 불일치(IsActive분기) → 자세없음
}

// === C-4 ===
readonly struct TargetingResult { IReadOnlyList<BattleUnit> Targets; bool TargetLost; }

static class TargetingSystem
{
    TargetingResult Resolve(ActionCommand command,
                            IReadOnlyList<AllyUnit> allies,
                            IReadOnlyList<EnemyUnit> enemies);   // 스킬계열 명령서만
}

// === C-5 ===
sealed class ActionResolver : IActionExecutor
{
    ActionResolver(IReadOnlyList<AllyUnit> allies, IReadOnlyList<EnemyUnit> enemies);
    void Execute(ActionCommand command);                                    // 12스텝 파이프
    DamageResult PreviewDamage(BattleUnit actor, BattleUnit target, SkillData skill);  // 예상피해(적용X)
}
```

### 정비 후 데이터·유닛 인터페이스 변경점

## 4. 의존성

- **이전 대주제**
  - A: `BattleUnit`(MaxHP/CurrHP/Shield/EvasionCount/IsIncapacitated, `EffectiveAttack/Defense/Speed`, 통로 `ModifyHP`/`SetShield`/`SetEvasion`/`SetIncapacitated`), `AllyUnit`/`EnemyUnit`, `RuntimeStats`, `SkillData`, `UnitStats`, `AttackDirection`/`TargetRule`/`ActionKind`.
  - B: `ActionCommand`(팩토리 `CreateSkill`/`CreateEndTurn` 등), `IActionExecutor`, `EnemyIntent`, `IntentSystem`, `BattleFlowSystem`.
- **레포 SSOT 표기 주의**(설계문서와 다른 지점, 레포 우선): `ActionKind.Defense`(문서 DirectionDefense 아님), `ActionCommand.CreateDefense`, `UnitStats.MaxHP`/`RuntimeStats.ModifyHP`/`CurrHP`, `EnemyUnitData.MaxBreakGauge`/`MaxCrackGauge`.
- **외부 에셋**: `Skill_`/`Ally_`/`Enemy_` SO — 정비 커밋으로 재저작 완료 가정.
- **패키지**: 없음(Unity 표준). `ActionResolver`/`BattleFlowSystem`만 `UnityEngine`(Debug.Log) 의존.

## 5. 검증 결과

각 소주제 임시 프로브(`_Scratch/`, 커밋 제외)로 확인, 전부 통과("문제 없어").

- **C-1**: 방어보정(100/(100+def)), 계수+고정, 방향 0.30, 붕괴 1.50, 최소1, 예상==실제, 회복·보호막 무보정 — 손계산 대조 전부 일치.
- **C-2**: 보호막 가산, 흡수<보호막(HP 불변), 흡수>보호막(전소+HP), 초과회복 클램프, 과다피해 HP 하한 0 — 통과.
- **C-3**: None공격 1.00, 약점 1.25, 일치 0.30, **아군불일치 0.75 vs 적불일치 1.00**(IsActive 분화 핵심), 방패자세 우선순위(약점>방어>불일치) — 통과.
- **C-4**: 단일 생존/대상상실, Self, 범위 진영 생존만(슬롯 순서), 진영 전멸 대상상실 — 통과.
- **C-5**: 단일공격 예상==실제, 보호막 흡수 경로, 대상상실 행동취소, 회복(Self), 범위, **풀루프(BattleFlowSystem+ActionResolver → 적 intent가 아군 실제 타격 = B 구멍 메워짐)** — 통과.
- **정비 커밋 회귀**: 컴파일 통과 + 에셋 재저작 후 B 턴루프·C-5 프로ب 재실행, 풀루프 `✓`.

> 프로브는 컴파일·런타임 동작만 보장. 밸런스 수치 검증은 플레이테스트 몫.

## 6. 확정 설계 결정 (근거 압축)

1. **CombatCalculator 입력 = primitive**(BattleUnit 아님). UnityEngine-free 헤드리스 테스트 + 손계산 대조 자명. 호출 경로가 ActionResolver 하나뿐이라 예상=실제는 그 경로가 보장.
2. **배율값 = DirectionSystem `static readonly` 단일 소유**. BattleConfig SO 미생성 → APSystem 선례와 동일 방식. SO 이관은 D·E까지 배율 모인 뒤 일괄(부채).
3. **DirectionSystem = 순수 함수, 자세는 파라미터**. RuntimeStats 자세 저장은 D-4 소유 → C는 안 건드림. 파이프는 `DefenseStance.None` 주입 → 풀 파이프 방향배율 1.00, 방향 로직 검증은 C-3 프로브에서.
4. **DamageResult = FinalDamage + 실제 배율(float) 동봉**. 적용여부 bool 대신 배율 보관 → 계산기 안에 float 비교 안 둠, UI가 `mod != 1f` 파생.
5. **보호막 소유 분리**: 흡수=DamageSystem(피해 파이프 불가분), 부여=ShieldSystem. HP를 Damage(−)/Healing(+) 둘이 쓰는 선례와 정합. 중첩=**가산**(GDD 규칙 없음 → 결정론적 가법).
6. **효과 라우팅 = 피해/회복/보호막 독립 적용**(wide SkillData). `HasDamage/HasHealing/HasShield` 각 검사. 방향 배율은 피해에만 주입(회복·보호막 무보정, GDD 5.6).
7. **예상=실제 = ActionResolver.ComputeDamage 단일 경로**. 미리보기·실제가 같은 private 메서드 호출 → 구조적 동일 보장. (Resolver 분리가 보장하는 게 아님 — 이 단일 경로가 열쇠.)
8. **[리뷰 반영] DefenseStance.MismatchMod(float) → IsActive(bool) 전환**. C-3 최초 코드가 밸런스 배율을 Data 구조에 복사해 결정2를 자기 위반 → 리뷰에서 발견. IsActive는 능동/패시브(자세의 물리 속성)만 알리고, 배율값은 DirectionSystem에 100% 잔류. 안1 취지("판정 함수가 진영 무지")는 유지(active/passive는 진영 분기가 아님).
9. **[정비] 스킬·유닛 참조를 문자열 ID → 인스펙터 직접 참조**. 편집 시점 안전성 확보(부채 #3 해소), 리졸버 제거. 단 각 SO의 자기 `id` 필드는 세이브·로그·로드 재바인딩 키로 유지(하이브리드). `behaviorPatternId`는 팩토리 키라 참조 대상 없음 → 문자열 유지. `effectIds`/`statusImmunityIds`는 StatusEffectData(E) 생성 시 참조화.
10. **[정비] DisplayName 필드 추가**(SkillData/AllyUnitData/EnemyUnitData + 런타임 유닛). id(안정 키, 불변)와 표시명(한글, 가변) 분리. 코드 분기 금지, 표시 전용. 폴백 없음(빈 값 노출 → 미저작 조기 발견). 다국어는 YAGNI로 보류(필요 시 로컬라이즈 키로 재해석).

## 7. 기술 부채

### 해소됨 ✅

- **[구]#3 문자열 ID 컴파일 안전성 0** → 참조화로 해소(오타 ID 런타임 생존 불가). 잔여: `effectIds`/`statusImmunityIds`/`behaviorPatternId`는 미해소(아래 이월).
- **결정2 자기 위반(DefenseStance가 밸런스 배율 소유)** → IsActive 전환으로 해소. 배율 단일 소유 복원.
- **[구]리졸버 스톱갭(`Func<string,SkillData>`)** → 참조 직독으로 제거. BattleFlowSystem 생성자 인자 1개·간접 1개 삭제.

| C | 보호막 흡수·부여가 `SetShield` RMW | `DamageSystem`/`ShieldSystem` | D에서 보호막 대응 붙일 때 `ModifyShield(delta)` 통로 추가 여지 |
| D | 배율 상수 하드코딩(static readonly) | `DirectionSystem` | D·E까지 배율 모인 뒤 `BattleConfig` SO 일괄 이관(AP 상수와 함께) |
| E | 로스터 참조 배선 함정 | `ActionResolver`+`BattleFlowSystem` | 둘에 **같은 allies/enemies 인스턴스** 주입 강제 장치 없음. 실전 부트스트랩이 로스터 1회 생성 후 양쪽 주입 |
| F | 범위 타겟팅 = 대표 진영 규칙 | `TargetingSystem` | 적 힐/보호막 스킬 + G 대상선택 도착 시 재검증(현 더미 intent는 항상 첫 생존 아군 대표) |
| G | `effectIds`/`statusImmunityIds` 문자열 잔존 | `SkillData`/`EnemyUnitData` | E에서 `StatusEffectData` 생성 시 참조화 |
| H | DisplayName 단일 언어 하드코딩 | 3 데이터 SO | 다국어 필요 시 로컬라이즈 키 테이블로 재해석(현재 YAGNI) |
| I | `Dictionary` 순회 비결정성 | `IntentSystem`(B 이월) | 고우선순위. 결정론 원칙과 충돌 소지 |

## 8. 후속 대주제 훅 위치 (D/E가 채울 스텁 — 코드 내 주석으로 표시됨)

### D-1 보호 (ProtectionSystem)
- **훅**: `TargetingSystem.Resolve` 내부 "3. 보호 리다이렉트 [D-1 자리]" 주석.
- **작업**: `rule==Single`일 때만 `ProtectionSystem.GetProtector(designated)` → 대상 교체. FixedTarget·Area는 리다이렉트 제외(로직 이미 분기됨). `Resolve`에 `ProtectionSystem` 파라미터 1개 추가 = 호출자(ActionResolver) 1줄 churn.

### D-2 회피 (EvasionSystem)
- **훅**: `ActionResolver.ResolvePerTarget` 상단 "5. 회피 판정 [D-2 스텁]" 주석.
- **작업**: `EvasionSystem.HasEvasion(target)` → 있으면 `Consume(target)` 1 소모 후 이 대상 통째 무효(6~12 스킵, 12 상태이상도 함께 무효). C 유닛은 `EvasionCount` 항상 0이라 현재 무해.

### D-3 붕괴/균열 (Break/CrackSystem)
- **훅 1**: `ActionResolver.ResolvePerTarget` "10~11. 붕괴/균열 [D-3 스텁]" 주석 — 생존 && `skill.BreakAmount>0` → `Accumulate` → `CheckAndTrigger`(사망 동시엔 발생 안 함). 파이프 8~11 순서가 소급/사망동시 함정 자동 해결.
- **훅 2**: `ActionResolver.ComputeDamage`의 `float breakMod = 1.00f` — 붕괴 상태 대상은 받는피해증가 배율(1.50) 주입으로 교체.
- **훅 3**: `BattleFlowSystem.IsStillValid`의 "붕괴 취소 판정. 미구현" 주석 — 붕괴로 행동 취소. **선행 필요**: `BattleUnit.actedThisTurn` 플래그 추가(현재 없음, 묶음2 2-B 예정).

### D-4 방향방어·자세 배선
- **훅**: `ActionResolver.ComputeDamage`의 `DirectionSystem.GetMod(skill.Direction, DefenseStance.None)` — `None`을 방어자 실제 자세로 교체.
- **작업**: `RuntimeStats`에 방어방향·약점방향·IsActive 저장 필드 추가 + 응답단계(방향방어 명령) 배선 + 웨이브 종료 시 자세 제거(F). `DefenseStance` 타입은 C-3에서 이미 정의됨.

### E 상태이상 (StatusEffectSystem)
- **훅 1**: `ActionResolver.ResolvePerTarget` "12. 동반 상태이상 [E 스텁]" 주석 — `skill.EffectIds` → 부여. 회피 시 5에서 함께 무효.
- **훅 2**: `CombatCalculator.CalcHealing`의 `receivedHealingMod`(현재 호출자가 1.00f 주입) — 중독 등 받는회복량 보정.
- **작업**: `StatusEffectData` 타입 생성 → `SkillData.effectIds`·`EnemyUnitData.statusImmunityIds` 참조화(부채 G 해소).
