## 2. 핵심 구조

```
[Data]  EffectKind(enum, 7종)  StatusEffectCategory(enum: Normal/Special/Buff)  EffectComponent(struct)
        StatusEffectData(SO): _statusId + _category + _baseDuration + List<EffectComponent>
             ▲ 직접 참조 (구 string id 폐기)
        SkillData.Effects[]   EnemyUnitData.StatusImmunities[]

[Core]  RuntimeStatusEffect: StatusEffectData(정적) + AppliedTurn(불변) + RemainingDuration + DamageSnapshot
[Core]  RuntimeStats: List<RuntimeStatusEffect> + 집계(Sum/Product/Has) + _breakDamageMod(붕괴 전용, 상태이상과 물리 분리)
[Core]  BattleUnit: 집계 위임 + 유효스탯(DefenseModifier/SpeedModifier = 부호델타 합산)

[Systems] StatusEffectSystem: Apply / Cleanse / TickAll / DecrementAndExpire   (규칙 소유, UnityEngine 미의존)
[Systems] BattleFlowSystem.Step8: 틱 → 전투불능 전이(인라인) → 지속감소·만료 → 전투상태 만료   (조율·로그)
[Systems] ActionResolver: 12스텝 부여/정화 · ComputeDamage(받는피해증가/받는회복보정)
[Systems] CombatCalculator: 정수 스케일 계산(CalcDamage/CalcHealing/CalcShield/CalcFlat), Scale=100 SSOT
[Systems] APSystem.RecoverAll: AP회복보정 부호델타
```

**레이어 규율 핵심**: asmdef는 `Systems → Core → Data` 단방향. Core(BattleUnit)는 Systems를 참조 못 함. 따라서 **집계(파생 조회)를 Core(RuntimeStats)가 소유**(안A). 유닛 접근자와 System 소비처가 같은 Core 헬퍼 하나를 공유 → SSOT 단일. 규칙(면역·중첩·정화·틱·만료)만 Systems(StatusEffectSystem).

**계산 규율 핵심**: 모든 피해/회복/보호막/스냅샷 계산은 `CombatCalculator`가 **정수 스케일 산술**로 독점 수행. float 계수·배율은 진입점에서 `Round(×Scale)`로 정수화(표현오차 흡수) → 이후 정수 연산 → 오차 0, 플랫폼 재현성.

## 3. 공개 인터페이스 (F·후속이 호출·의존)

### StatusEffectSystem (static, Systems)
- `void Apply(BattleUnit target, StatusEffectData def, BattleUnit caster, int currentTurn)` — 면역→스냅샷→중첩/신규
- `void Cleanse(BattleUnit target)` — `category==Normal`만 제거
- `void TickAll(IEnumerable<BattleUnit> units, int currentTurn)` — 지속피해 틱 (적용턴 지난 것)
- `void DecrementAndExpire(IEnumerable<BattleUnit> units, int currentTurn)` — 지속감소 + 만료제거
- **[F 미구현] `ClearNormal`** — 웨이브 복귀 유닛 상태 제거. `Cleanse`는 Normal만 지우므로, F는 `{Normal, Buff}` 제거 필요(버프는 원래 전투상태였음, GDD 5.16)

### BattleUnit (Core) — 집계 위임
- `float SumStatusMagnitude(EffectKind kind)` — 합산형(Speed/Defense/APRecovery)
- `float ProductStatusMagnitude(EffectKind kind)` — 곱셈형(ReceivedDamage/ReceivedHealing), 기본 1.0
- `bool HasStatusComponent(EffectKind kind)` — 존재형(ActionBlock)
- `IReadOnlyList<RuntimeStatusEffect> StatusEffects` — 읽기
- `RuntimeStatusEffect FindStatusEffect(string statusId)` — 중첩 조회

### RuntimeStatusEffect (Core)
- `bool IsTickable(int currentTurn)` = `currentTurn > AppliedTurn` (지속피해 틱·지속감소 공통 게이트)
- `void Decrement()` / `bool IsExpired` / `RefreshDuration(int)` / `RefreshSnapshot(int)`

### CombatCalculator (static, Systems) — 계산 단일 소유
- `DamageResult CalcDamage(int attack, float damageCoeffi, int fixedDamage, int defense, float directionMod, float breakMod, float receivedDamageMod)` — **7인자**. 받는피해증가 없으면 `1.00f`.
- `int CalcHealing(int attack, float healingCoeffi, int fixedHealing, float receivedHealingMod)`
- `int CalcShield(int attack, float shieldCoeffi, int fixedShield)`
- `int CalcFlat(int attack, float coeffi)` — 배율·방어 없는 순수 계수 곱(지속피해 스냅샷 등). **정수화 로직 재사용 진입점**
- 내부: `const int Scale = 100` (배율·계수 유효 소수 2자리, 값의 단일 소유), `ToScaled`(진입점 반올림)

## 5. 검증 결과 + 리뷰 결과·반영

### 통합 검증
- 프로브: `Assets/_Scratch/E_IntegrationProbe.cs` (커밋 제외, 리플렉션으로 SO private 필드 주입)
- 결과: **PASS 23 / FAIL 0**
- 커버리지: A(부여·면역·중첩·독립·정화 5) / B(지연틱·마지막틱·보호막흡수·독립틱·지속감소지연 5) / C(방어저하·둔화·AP회복·받는회복·받는피해증가채널분리 5) / D(증가버프·순델타·정화면제·AP증가 4) / E(8단계 틱 실동작·전투불능 전이 2)
- C5 최종피해: 정수 스케일 도입으로 `100×1.5×1.3=195` **정확**(이전 float 오차 194 해소, ±1 근사 assert 제거)

### 코드 리뷰 (트리거: E-3 검증 통과 직후)
- **[높음·반영] 증가 버프 미수용**: 합산형 소비처가 뺄셈(마이너스)을 하드코딩해 증가 버프 표현 불가. → **magnitude를 부호 있는 델타로 재정의**(저하 음수/증가 양수), 소비처 덧셈 통일. `EffectKind` 규약·`BattleUnit`·`APSystem` 수정. 방향(증감)을 데이터(magnitude 부호)가 소유 → Core는 순수 덧셈만(SSOT·레이어 정합 개선).
- **[중간·반영] 증가 버프 소속 = 갈래1**: 버프를 상태이상 목록 내 편입. `StatusEffectCategory.Buff` 신설(정화 면제). 부여·집계·틱·만료·중첩은 통로 재사용, 정화만 category로 자동 면제 → enum 1개 추가로 완결.
- **[중간·이월]**: BreakCrackSystem 메서드명 혼동 / 전투불능 유닛 틱 미배제 / 8단계 전이 그물망 성격 (아래 부채·훅)
- **[낮음·기록]**: 집계 yield 재순회 / (int) 절삭 규약 / caster null 불허
- **자기위반**: 없음

### 리뷰 후속 — 정수 스케일 미니작업 (float 정밀도 부채 해소)
- 통합 프로브 C5가 float 표현오차(`1.3f`≈1.29999995 → 195 대신 194)를 드러냄. 결정론은 유지되나 "의도한 정수 피해"가 계수에 따라 −1 흔들림.
- **해소안 B1 채택**: 계산 진입점에서 `Round(계수·배율 × Scale)`로 정수화(반올림이 표현오차 흡수) → 이후 정수 산술. 곱은 분수(분자/분모)로 모아 **마지막에 floor 1회**(GDD 5.6 "맨 끝 버림" 정확 준수). `long` 누적으로 오버플로 방지.
- **B1 vs B2**: B1(진입점 정수화)이 이미 오차 0을 달성하므로, SO 필드를 정수 저장(B2)할 명분 없음. 배율·계수는 **float 저장 유지**(밸런싱 직관 "1.3배" 보존), 정수화는 계산 경계에서만.
- **수정 파일**: `CombatCalculator`(정수 스케일 재설계 + `CalcFlat` 추가), `StatusEffectSystem.ComputeDamageSnapshot`(`CalcFlat` 위임). **무수정**: `DirectionSystem`·`BreakCrackSystem`·`SkillData`·`EffectComponent`·`DamageResult`(배율·계수 float 저장 유지, 시그니처 불변).

## 6. 확정 설계 결정 (근거 압축)

1. **집계 위치 = Core (안A)**: Core는 Systems 참조 불가(asmdef 단방향). 집계를 RuntimeStats가 소유해 유닛 접근자·System 소비처 공유. 규칙만 StatusEffectSystem.
2. **받는피해증가 채널 물리 분리 (부채-1 해소)**: 붕괴는 `_breakDamageMod`(전용 필드), 상태이상 받는피해증가는 목록 조각(필드 없음). `IsBroken`(=`BreakDamageMod > 1.00`) 오염 차단. 필드 개명이 방어선.
3. **받는피해증가 곱 합성 = CalcDamage 인자**: GDD 5.6 "기타 명시적 보정" 별개 단계. `DamageResult.BreakMod`/`ReceivedDamageMod` 분리 저장. breakMod에 곱해 섞지 않음.
4. **magnitude 부호 델타 (합산형)**: Speed/Defense/APRecovery = 부호 델타(저하 −/증가 +). 증가 버프 같은 kind·같은 통로 수용. 곱셈형(ReceivedDamage/ReceivedHealing) = 배율(1.0 기준, 증감 대칭).
5. **증가 버프 = 갈래1**: 상태이상 목록 내. `StatusEffectCategory.Buff`(정화 면제). GDD 일시강화를 상태이상으로 재분류 예정.
6. **자료구조 = List (Dictionary 아님)**: 결정론(삽입 순서). 중첩 조회 선형 탐색(최대 7종). Dictionary 순서 부채 회피.
7. **magnitude = float** 통일. 스탯 파생은 `(int)` 절삭.
8. **타이밍**: 스탯 파생 = 즉시 활성(적용턴 무관). 둔화 "다음 글로벌 턴부터"는 7단계 정렬이 턴당 1회 + 부여가 항상 7단계(정렬 후)라 자연 보장. 지속피해 틱·지속감소만 `IsTickable`(`currentTurn > AppliedTurn`) 게이트.
9. **8단계 순서**: 틱 → 전투불능 전이(인라인, F 수렴 예정) → 지속감소·만료 → 전투상태 만료. 틱이 감소보다 앞이라 마지막 틱 보존.
10. **StatusEffectSystem 순수**(UnityEngine 미의존). 틱 로그는 조율자 BattleFlowSystem이 틱 전후 HP 비교로 담당. 헤드리스 규율 유지.
11. **중첩**: 합산 안 함. 강한 스냅샷·긴 지속 유지, `AppliedTurn` 불변(재부여는 연장이지 새 인스턴스 아님).
12. **스냅샷**: 부여 시 `caster.EffectiveAttack × 계수` 1회 고정(`CalcFlat` 경유). 이후 공격력 변화·방어·방향·붕괴 무보정(GDD 5.12).
13. **지속피해 보호막 흡수 O** (GDD 5.6). `DamageSystem.Apply` 통로 직행.
14. **참조 전환**: SkillData.Effects, EnemyUnitData.StatusImmunities = StatusEffectData 직접 참조. 각 SO 자기 statusId는 세이브용 유지(하이브리드).
15. **정수 스케일 계산 (B1)**: 계산 진입점에서 계수·배율을 `Round(×Scale=100)` 정수화 → 분수 누적 → 마지막 floor 1회. float 표현오차 흡수 + 플랫폼 재현성. 배율·계수는 float 저장 유지. 계산 로직·`Scale` 값은 `CombatCalculator` 단일 소유.

## 7. 기술 부채

### 해소
- **부채-1 (DamageTakenMod 채널 충돌)** → 해소. `_damageTakenMod`→`_breakDamageMod` 개명 + 상태이상 받는피해증가를 목록 조각으로 물리 분리. `IsBroken` 판정이 상태이상에 오염되지 않음.
- **부채-2 (Step8 받는피해증가 만료가 적만 순회)** → 해소. 상태이상 만료는 `DecrementAndExpire`가 전체 유닛 순회. 붕괴 만료만 적 순회(정확). Step8 확장 불필요.
- **float 배율 × floor 경계 민감성** → 해소. 정수 스케일 계산(결정 15) 도입. `1.3f` 등 이진 무한소수 계수의 −1 흔들림 제거, 플랫폼 재현성 확보. C5 정확 195 복원.
