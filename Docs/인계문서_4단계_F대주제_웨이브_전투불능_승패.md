## 2. 핵심 구조

```
[F-1 전투불능 전이]
  IncapacitationSystem.CheckAndTransition(unit) : bool  (순수, HP0 && !전투불능 -> set, 멱등)
     ▲ 두 호출처가 이 단일 통로로 수렴 (HP0 핸들러 SSOT)
     ├─ ActionResolver.ResolvePerTarget 9스텝 (파이프 피해 후 즉시 전이)
     └─ BattleFlowSystem.Step8 2번 (지속피해 틱 후 전이)
  로그는 호출측(bool 반환) — IncapacitationSystem은 UnityEngine 미의존

[F-2 웨이브 전환]  WaveSystem.AdvanceToNextWave() = 전환순서 5~9 조율 (순서만, 소거는 담당 시스템)
  5. 전투상태 강제소거(아군)  ShieldSystem.ClearAll / EvasionSystem.ClearAll / _protection.ClearAll
                              / StatusEffectSystem.ClearBuff / a.ClearStance
  6·7. 전투불능 아군 HP1 복귀 + ClearNormal(복귀자만)   AP는 유지
  8. 생존 유닛 유지 = no-op
  9. 활성 적 리스트 내용 교체(같은 인스턴스 -> BattleFlow/ActionResolver 전파)
  10. 다음 턴 + AP+2 = BattleFlow 턴루프가 자연 처리(WaveSystem 밖)

[F-3 승패 판정]  BattleFlowSystem.Step9_Judge() : BattleOutcome
  전멸(전 아군 전투불능) -> Defeat            ← 승리보다 먼저(동시 HP0 자동 패배)
  현 웨이브 적 전멸 + 남은 웨이브 -> AdvanceToNextWave + Ongoing
  현 웨이브 적 전멸 + 마지막 -> Victory
  [D6 스텁] CheckPhaseTransition() -> false (페이즈 별 경로 자리)
  그 외 -> Ongoing
  ExecuteTurn()이 Step9 반환값을 그대로 반환 -> 상위 루프가 while(Ongoing) 제어
```

**레이어 규율**: 3종 신규 전부 asmdef 단방향 준수. `IncapacitationSystem`·`WaveSystem`(Systems)은 Core·Data만 참조, `BattleOutcome`(Data)은 참조 없음. Systems가 `BattleOutcome` 반환 = Systems→Data 정방향.

**소거 통로 이원화 완결**: 턴종료 만료(`DecrementAndExpire`, 조건부) vs 웨이브 강제소거(`ClearAll`/`ClearBuff`/`ClearNormal`, 무조건). 계기가 다른 연산이라 통로 분리. `RemoveByCategory` private 헬퍼로 `Cleanse`/`ClearNormal`/`ClearBuff` 공통 로직 SSOT.

## 3. 공개 인터페이스 (후속·상위 루프가 호출·의존)

### IncapacitationSystem (static, Systems)
- `bool CheckAndTransition(BattleUnit unit)` — HP0 && !전투불능 → set + true. 멱등(이미 전투불능이면 false). 로그는 호출측.

### WaveSystem (Systems, 인스턴스)
- 생성자 `(List<EnemyUnit> activeEnemies, IReadOnlyList<IReadOnlyList<EnemyUnit>> waves, IReadOnlyList<AllyUnit> allies, ProtectionSystem protection)`
- `int CurrentWaveIndex` / `bool HasNextWave` — 마지막 웨이브에서 false
- `void AdvanceToNextWave()` — 전환순서 5~9 실행. `!HasNextWave` 시 `InvalidOperationException`. 호출 조건 판정은 F-3(Step9) 소유
- **[계약 함정] `waves[0]` 내용은 무시됨**: 첫 전환이 index 1을 읽음. `waves[0]`은 개수 세기(`HasNextWave`)에만 쓰이고 활성 적은 셋업이 직접 채움 → 셋업 시 `activeEnemies`와 `waves[0]`을 일치시킬 것(M1)

### BattleFlowSystem (Systems)
- `BattleOutcome ExecuteTurn()` — 반환 타입 void→enum. 상위 루프: `while (flow.ExecuteTurn() == BattleOutcome.Ongoing) { }`
- 생성자 파라미터 변경: `enemies`가 `IReadOnlyList`→`List<EnemyUnit>`, 끝에 `WaveSystem waveSystem` 추가

### StatusEffectSystem (static, Systems) — 소거 통로
- `void ClearNormal(BattleUnit target)` — 복귀 유닛 Normal 제거(복귀자만, 생존자 유지). 현재 `Cleanse`와 동일 연산
- `void ClearBuff(IEnumerable<BattleUnit> units)` — Buff 전원 제거(전투상태 강제소거, D4)

### ShieldSystem / EvasionSystem (static, Systems)
- `void ClearAll(IEnumerable<BattleUnit> units)` — 보호막/회피 전원 0

### BattleOutcome (Data, enum)
- `Ongoing`(웨이브 전환 포함 전투 계속) / `Victory`(마지막 웨이브 적 전멸) / `Defeat`(전 아군 전투불능)

### 코드 리뷰 (트리거: F-3 검증 통과 직후)
- **[중간·반영] M4 복귀 HP1 불변식 의존**: `ModifyHP(1)`→`ModifyHP(1 - a.CurrHP)`. "전투불능 ⟹ HP0" 불변식과 무관하게 항상 HP1 보장. 정상 경로 동작 불변(HP0에서 결과 동일), 회귀 PASS 유지
- **[낮음·유지] L1 페이즈 스텁 분기**: `if(CheckPhaseTransition()) return Ongoing;` 다음도 Ongoing이라 형식상 죽은 코드지만, 페이즈 확정 시 리셋+Ongoing 삽입 자리표시로 **의도적 유지**
- **[중간·종결] M2 전투불능 유닛 8단계 틱·감소 미배제**: E 이월 부채. F 최종 판단 = **미배제 유지로 종결**. 틱은 HP0 클램프라 무해, 감소로 만료돼도 복귀 시 `ClearNormal`이 재차 제거. 대상후보·AP회복은 이미 각자 배제 중 → "통일" 실익 낮음. 순회 낭비만 남고 버그 없음
- **[중간·기록] M1 waves[0] 무시 계약** / **[중간·기록] M3 WaveSystem Debug 의존 부채 목록 누락**
- **[낮음·기록] L2 Cleanse=ClearNormal 완전 동일** / **L3 `_enemies` 소유권 모호(D2 트레이드오프)** / **L4 ClearBuff 아군만**
- **자기위반(정직 보고)**: D5는 "3개 시스템에 ClearAll"이었으나 `BreakCrackSystem.ClearAll`은 미생성. 웨이브 전환은 적 교체라 게이지 소거 무의미, 실사용처는 페이즈 전환(D6 미확정)뿐이라 페이즈 확정 시로 이월. 근거 있는 조정이나 결정 문서와 코드 차이를 기록

## 6. 확정 설계 결정 (근거 압축)

1. **[D1] HP0 핸들러 = `IncapacitationSystem` 단일 소유**: 파이프(피해 후)·Step8(틱 후) 두 발생점이 한 통로 수렴. 얇은 유닛(규칙은 시스템, 유닛은 `SetIncapacitated` 통로). 파이프가 로그만 찍고 전이 안 하던 버그 해소. bool 반환으로 순수 유지(로그는 조율자)
2. **[D2] 웨이브 데이터 = 코드 주입, EncounterData SO는 자리만**: F 본질은 전환 시퀀스·복귀·판정. 인카운터 데이터 로딩까지 넣으면 스코프 크립. `_waves`가 후속 SO 대체 자리
3. **[D3] 전투 종료 = `BattleOutcome` enum 반환**: 헤드리스 로그에 이벤트는 과함. 웨이브 전환은 Ongoing에 흡수(전투 계속), 승리/패배만 종료 시그널. 상위 루프 `while(Ongoing)`
4. **[D4] 버프 웨이브 취급 — E인계문서 정정**: E훅 "ClearNormal={Normal,Buff}"는 묶음3 2-C(일시강화=전투상태 강제소거 전원)와 충돌. 문서 권위(공정표>GDD>묶음>인계) 따라 **묶음3 우선**. `ClearNormal`=Normal만(복귀자), 버프는 전환순서 5 `ClearBuff` 전원. 갈래1 편입은 저장 위치만 바꾼 것, 웨이브 취급은 GDD 원분류(전투상태) 유지
5. **[D5] 소거 = 각 시스템 ClearAll(God 방지)**: WaveSystem은 순서만, 소거 규칙은 담당 시스템. `ProtectionSystem.ClearAll` 패턴 계승. **단 BreakCrackSystem.ClearAll은 페이즈 전환 확정 시로 이월**(웨이브 전환엔 적 교체라 불요)
6. **[D6] 페이즈 전환 = 훅/스텁만**: v0.1.0 공개범위에 보스 2종 있으나 페이즈 전환 명시 없음(균열 게이지만). `CheckPhaseTransition`→false + Step9 별 경로 자리. 트리거·리셋은 보스 전용 시스템으로
7. **전투상태 강제소거 대상 = 아군 한정**: 전환순서 5는 "전원"이나 전환 조건이 "현 웨이브 적 전멸"이라 적은 곧 교체·관측 불가 no-op. 넘어가 싸우는 건 아군뿐
8. **활성 적 리스트 = 공유 인스턴스 내용 교체**: BattleFlow·ActionResolver·WaveSystem이 같은 `List` 참조. `Clear()`+`Add`로 내용만 교체 → 참조 불변, 전환 자동 전파. 별도 리스트 갈아끼우면 옛 참조가 안 따라옴
9. **복귀 HP1 = `ModifyHP(1 - CurrHP)`(M4)**: 불변식 비의존 방어식. `SetIncapacitated`가 public이라 미래 HP>0 전투불능 케이스에도 견고
